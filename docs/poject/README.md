## Что это за приложение

Персональный трекер вакансий. Локальный однопользовательский инструмент: хранит вакансии, добавленные вручную по ссылке, статус прохождения по каждой и умеет проверять, не снята ли вакансия с публикации.

Работает на машине кандидата, без облачных зависимостей. В сеть выходит только по нажатию кнопки: проверить активность или заполнить карточку через языковую модель. Ничего не запускается по расписанию.

## Текущее состояние

### Этап 1 (MVP) — готов

- Добавление вакансии по ссылке, ручная правка карточки.
- Таблица с сортировкой по любому столбцу, неактивные скрыты по умолчанию.
- Статус кандидата: отклик, этап собеседования, контакт HR, зарплаты, сопроводительное письмо.
- Проверка активности по кнопке — одной вакансии или всех сразу.
- Ручное решение об активности сильнее результата проверки; расхождение показывается, но не исправляется само.

### Резервные копии — готово

Снимок всей базы одной кнопкой и восстановление из него. Сверх ТЗ: понадобилось после того, как база один раз пострадала от связки WAL с bind-mount. Перед восстановлением приложение само снимает копию текущего состояния, поэтому ошибочное восстановление обратимо. Механика — в [`structure.md`](./structure.md#резервные-копии), эндпоинты — в [`api.md`](./api.md#резервные-копии).

## Объём кода и проверок

| Часть | Размер | Проверки |
|---|---|---|
| Backend (Go) | ~6 100 строк кода в 10 пакетах | 234 теста в 9 пакетах (~7 300 строк): unit + интеграционные поверх in-memory SQLite |
| Frontend (React) | ~4 200 строк | 184 проверки в `npm run smoke` (рендер экранов в строку) |

Автоматических тестов на фронте нет по решению при проектировании: интерфейс проверяется руками, а смоук страхует от несобираемого состояния и битых импортов.

## Ключевые принципы, заложенные в код

**Ручное решение важнее автоматики.** Активность вакансии хранится в двух полях: результат проверки и решение пользователя. Отображаемое значение — `manual ?? auto ?? true`. Проверка никогда не перезатирает ручной выбор, только показывает расхождение.

**Ничего не происходит само.** Нет крона, нет фоновых задач. Каждый запрос к внешнему сайту и к языковой модели инициирует пользователь нажатием кнопки.

**Модель ничего не пишет напрямую.** Извлечённые поля возвращаются на предпросмотр, а запись идёт обычным `PATCH` после подтверждения. Путь записи в вакансию остаётся один.

**Нет авторизации — значит, нет и внешнего доступа.** Порт публикуется только на `127.0.0.1`. Это осознанное решение из ТЗ, а не упущение.

**Разрушительные действия обратимы.** Восстановление базы заменяет все данные, поэтому перед ним снимается копия текущего состояния. Удаление копии, наоборот, требует подтверждения, но автоматической чистки старых копий нет: занять место безопаснее, чем удалить данные без спроса.
