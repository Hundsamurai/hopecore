# ТЗ: Персональный трекер вакансий

## 1. Цель проекта

Локальное (single-user) приложение для кандидата, которое:
1. Хранит базу вакансий, добавленных вручную по ссылке.
2. Раз в сутки (крон) опрашивает эти ссылки и обновляет статус активности вакансии.
3. Хранит статус прохождения кандидатом каждой вакансии (от отклика до оффера).
4. Хранит резюме прошедших собеседований и блок AI-аналитики (прогноз зарплаты/оценка соответствия рынку).
5. Отдаёт всё это через простую тёмную админ-панель.

Нагрузка минимальная (один пользователь, десятки-сотни вакансий), поэтому сложность архитектуры должна быть сознательно занижена — это внутренний инструмент, а не продукт.

---

## 2. Технологический стек (утверждено)

- **Backend:** Go — REST API + модуль парсинга/интеграции с LLM-провайдерами.
- **Frontend:** React (Vite) — админка.
- **БД:** SQLite, локальный файл.
- **Авторизация:** не нужна — строго локальный однопользовательский инструмент.

Supabase и облачные зависимости исключены — вся система работает офлайн на машине кандидата.

---

## 3. Источники данных и парсинг

Два независимых режима заполнения/обновления вакансии — не взаимоисключающие, кандидат выбирает по ситуации:

### Режим 1 — Ручное заполнение
Кандидат вставляет ссылку на вакансию и вручную заполняет все поля карточки (грейд, теги, компания, статус и т.д.). Никакого автоматического похода в сеть не происходит. Базовый режим, всегда доступен, ничего не стоит по API-квоте.

### Режим 2 — Опрос через MCP-агента / LLM по фильтрам
Кандидат задаёт критерии поиска (грейд, стек/теги технологий, зарплатная вилка, регион/формат работы и т.п.), после чего:
- если для источника есть MCP-сервер с официальным API (например, hh.ru) — запрос идёт через него;
- если структурированного API нет (например, вручную вставленная ссылка на произвольный сайт вакансии типа tbank.ru/greensight.ru/job.alfabank.ru) — страница скачивается, и поля извлекаются LLM-запросом со структурированным JSON-ответом вместо HTML-селекторов под каждый сайт.
- Тот же механизм (не отдельный) используется и для обновления статуса «активна/не активна» уже добавленной вакансии, и для нейроблока (п.6) — не дублируем LLM-обвязку.

**Важно: никакого автоматического крона.** Оба варианта режима 2 запускаются **только вручную, по кнопке** — и сам запуск сразу нужен в MVP (см. п.8), и выбор LLM-провайдера на конкретный запуск — тоже ручной (см. п.7).

## 5. Функциональные требования (backend)

1. CRUD по вакансиям — добавление по ссылке, поля заполняются либо вручную (Режим 1), либо запуском LLM/MCP-обзвона по кнопке (Режим 2).
2. Ручной запуск обновления статуса активности («опросить сейчас») по одной вакансии или по всем сразу — без фонового крона.
3. Перед каждым запуском Режима 2 — выбор LLM-провайдера из списка (Gemini / Claude / DeepSeek).
4. CRUD по статусу кандидата (привязан к вакансии, 1:1).
5. CRUD по резюме собеседования (привязано к статусу кандидата; данные приходят из внешних систем — трекер их только хранит/показывает).
6. Нейроблок: по кнопке формирует прогноз ЗП и оценку соответствия рынку для вакансии, тем же выбранным LLM-провайдером.

---

## 6. Требования к интерфейсу (админка)

- Внешний вид — типичная админ-панель, тёмная тема.
- Слева — сворачиваемая меню-панель с вкладками (поп-ап/склатки-табы).
- Основной экран — таблица вакансий:
  - сортировка по умолчанию — по дате изменения;
  - неактивные вакансии скрыты по умолчанию (с возможностью показать);
  - клик по строке открывает карточку вакансии со статусом кандидата, резюме собеса и нейроблоком.
- Простой, функциональный, без лишнего декора.

---

## 7. Нефункциональные требования

- Один пользователь, без авторизации — инструмент строго локальный.
- Хранение секретов (API-ключи Gemini/Claude/DeepSeek) — через переменные окружения, не в коде.
- LLM-провайдер выбирается пользователем перед каждым запуском, ничего не вызывается автоматически/по расписанию — все траты по API-квоте инициирует сам кандидат.
- Логирование ошибок запросов к внешним источникам и LLM в файл/консоль, без необходимости алертинга — это личный инструмент.

---

## 8. MVP и этапы

**Этап 1 (MVP):** ручное добавление вакансии по ссылке (Режим 1) + таблица + карточка вакансии с ручным заполнением статуса кандидата + кнопка ручного запуска обновления статуса активности (без LLM).
**Этап 2:** Режим 2 — запуск LLM/MCP-обзвона по кнопке с выбором провайдера (Gemini/Claude/DeepSeek), автозаполнение полей вакансии.
**Этап 3:** нейроблок (прогноз ЗП по кнопке) + приём/отображение резюме собеса из внешних систем.
